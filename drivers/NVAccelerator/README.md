# NVAccelerator

The kernel side of Metal: an `IOGraphicsAccelerator2` subclass, so Metal.framework finds an
accelerator for the RTX 4080 and loads our `NVMTLDriver` bundle.

`IOAF2.hpp` is generated by `tools/b4/gen_ioaf2_headers.py` from the KDK's IOAcceleratorFamily2
binary, since Apple never shipped headers for it. Don't edit it by hand.

User clients open, the device enumerates, and Metal buffers get allocated through our own
`NVAccelSysMemory` subclass. The rest of the vendor hooks either do what AppleParavirtGPU does or log
and return something safe. Actual GPU work is driven from the Metal bundle through NVGspControl.

A panic in here would repeat on every boot, so the accelerator only starts after NVGspControl
publishes the `NVAcceleratorGo` resource, and userspace only asks for that after a clean GSP boot
(with a file-based crash guard, see `tools/nvaccel/`).

One thing to watch out for: don't put that gate back as `IOResourceMatch` on the GPU personality.
IOKit keeps the GPU busy while it waits for the resource, WindowServer times out waiting for the
GPU and the machine sits on the Apple logo forever. That's why there's a small `NVAccelLauncher` on
IOResources which polls for the resource and then starts the accelerator on the card itself.

Heads up, starting the accelerator while WindowServer is running still knocks the desktop off
(CoreDisplay goes looking for a display pipe we don't provide yet), so for now keep auto-start off
and start it by hand when testing Metal.
